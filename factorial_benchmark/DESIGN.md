# Factorial multi-strain benchmark

## Question

Separate three mechanisms that are confounded in the end-to-end
sk2bGrow-vs-Pilea comparison: sequencing depth, shared-anchor confusion in
multi-strain communities, and estimator choice.

## Design

The count-level simulator uses a 3 Mb circular chromosome and a fixed 5 kb
window grid. It does **not** emit FASTQ. Each community is generated by:

1. draw independent true `log2(PTR) ~ U(0,2)` for every strain;
2. draw abundance weights with either an even, 10:1, or 100:1 ratio;
3. assign Poisson counts to 5,000 landmarks under a V-shaped replication
   profile (`ori=0`, `ter=1.5 Mb`);
4. normalize window counts and standard errors by the number of landmarks in
   each window, so a random-sketch arm is not penalized for window-level
   density unevenness or Poisson heteroscedasticity;
5. for shared landmarks, draw one categorical source from abundance-weighted
   strain responsibilities, rather than assigning the count to every strain;
6. aggregate assigned counts into windows and apply both estimators to the
   same count table.

Factors:

| factor | levels |
|---|---|
| strain number | 4, 8, 16, 32 |
| per-strain depth | 0.5, 1, 2, 4, 8x |
| shared-anchor fraction | 0.00, 0.05, 0.15 |
| abundance ratio | even, 10:1, 100:1 |
| landmark source | coordinate-grid 2bRAD-like, random FracMinHash-like |
| estimator | coordinate V-fit, sorted-rank |

The two landmark arms have identical density (5,000 landmarks/genome). Thus
the contrast estimates the effect of coordinate placement and shared-anchor
handling at controlled density, not density. The two estimators see identical
assigned windows.

Excluding estimator, the full design has 360 factorial cells; including both
estimator arms, it has 720 cells. We use 10 replicates per cell and score every
strain, giving 54,000 genome-level estimates per estimator.

## Metrics

For every factorial cell and estimator:

- `n`, `n_ok`, `reported_fraction`
- bias in `log2(PTR)`
- RMSE in `log2(PTR)`
- mean absolute error
- Pearson correlation between true and estimated values
- within-cell paired difference against coordinate V-fit

## Storage policy

No FASTQ, BAM, per-anchor counts, or fitted objects are retained. Each array
task writes only aggregate rows to `results/part-*.tsv`. Expected final output
is under 20 MB. Scratch use is negligible because simulation occurs in memory.

## Runtime request

The factorial is split into 24 array tasks by strain number, abundance ratio,
and landmark source. Each task handles 150 communities.

| resource | request | rationale |
|---|---:|---|
| CPUs | 1 | vectorized NumPy; no mesh communication |
| memory | 2 GiB | observed maximum was 164 MiB; request headroom |
| wall time | 2 h | smoke-to-full range was 0.5-2 min/task |
| scratch | <10 MiB | aggregate TSV only |
| persistent output | <20 MiB total | aggregate TSV plus provenance |
